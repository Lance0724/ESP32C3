# 缺陷评估：联网校准时主循环心跳超时

- **名称**：calibration-ui-timeout
- **创建日期**：2026-11-12
- **来源**：用户报告P0完成后，第一个加热点P1持续缓慢升温，最终显示CALIB ABORTED / UI TIMEOUT；确认物联网开启，未注意到其他现象。
- **结论**：likely
- **严重程度**：high
- **根因置信度**：medium

## 实际与预期行为

- 实际：P1等待热平衡期间中止，停止原因为UI TIMEOUT。
- 预期：主循环持续运行校准状态机和本地输入；真正失联时仍在250ms心跳超时后停热。
- 缓慢升温尚未满足30秒稳定窗口时应继续等待；达到单点10分钟上限应显示POINT TIMEOUT，而不是UI TIMEOUT。

## 判断

同步网络处理与250ms主循环心跳约束冲突，是本次联网场景的明确高风险路径，与用户现象相符；尚无设备调用耗时记录，所以不把推测提升为实物根因已确认。温度慢升是固定功率寻求热平衡的独立现象，不直接触发UI TIMEOUT，也不据此放宽稳定阈值。

## 用户选择与契约调整

用户已在选项中明确选择pause_during_calibration：活动校准期间暂停物联网处理，结束或中止后自动恢复；页面提示网络暂停。用户已知晓活动校准期间远程关闭同样不可用，需现场长按停止。此项明确替代原计划“校准期间仍支持远程关闭”的要求；不静默缩减功能。

## 修复范围

- src/MIOT.cpp:run_task在校准active期间不进入Blinker.run，不改物联网配置或断开WiFi；退出活动校准后回到原联网逻辑。
- src/ui.cpp:calibration_draw在开启物联网且活动校准时显示本地停止/网络暂停提示，不覆盖温度、窗口、参考值。
- test/host/support/Blinker.h及test/host/run.py：注入同步网络耗时和监督回调；编译真实main.cpp，使回归覆盖真实loop而不只测试单独UI。
- test/host/calibration_test.cpp：P1期间注入超过250ms网络调用，证明主循环仍响应、未因网络等待误中止，本地取消能停热，结束后网络恢复且加热保持零。
- EC11与温度标定_PLAN.md、.ai/doc/ec11-temperature-calibration/requirements.md、specification.md：按用户批准更新活动校准远程不可用及自动恢复约定，保留历史已完成记录。
- 缺陷文档记录实际测试与上板限制。

## 不包含

不改250ms心跳、230℃保护、单点10分钟/总30分钟期限，不改校准功率、稳定温差或热平衡策略；不调整I2C、引入后台网络任务或重新设计网络库。

## 验证要求与风险

- 新回归必须执行实际loop，模拟网络调用期间PWM监督仍运行；不能只验证Blinker调用计数或配置字段。
- 保留既有故意断心跳导致停热的回归，确保暂停网络不掩盖真正UI失联。
- 同一轮运行主机全路径检查、生成实际像素预览、编译目标固件并检查最终镜像适配分区。
- 设备不可达时只能标为partial；连接后需在断开加热电源的条件下烧录并检查页面。完整P1热过程另需独立限温与可靠参考测点。
- 活动校准暂停网络意味着远程命令不能实时处理；不能依赖云端停热。传输层可能缓存消息，恢复后由既有协议处理，不宣称消息被永久丢弃。
