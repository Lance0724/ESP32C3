# 缺陷评估：温度校准页面黑屏

- **名称**：calibration-black-screen
- **创建日期**：2026-11-12
- **来源**：用户报告最新程序进入“温度校准”后黑屏。
- **结论**：confirmed
- **严重程度**：high
- **根因置信度**：high

## 实际与预期行为

- 实际：普通界面能显示，进入温度校准后全黑。
- 预期：128×32屏幕显示四行确认、采样、录入和退出提示。
- 触发：菜单第7项长按进入，calibration_enter设置CONFIRM，UI::run_task清屏后调用calibration_draw。
- 影响：所有校准状态的小字均不显示，用户无法安全观察校准过程。

## 复现与基线

用户报告作为复现依据，不重新运行故障固件确认现象。已读取实际绘制及测试路径；本次设备枚举只有COM1，没有可达的ESP32串口，不能进行上板验证。已检查缺陷目录位于项目根内、目录不存在且路径各组件均非符号链接。

## 代码与运行证据

| 位置 | 证据 | 判断 |
|---|---|---|
| src/ui.cpp:UI::calibration_draw | 四行文本全部调用oled.str，Size=8 | 新页面依赖6×8字符 |
| src/Oled.cpp:Oled::str | 只接受Size=16，其余直接return | 所有校准文字均未写入GRAM |
| src/Oled.cpp:Oled::write_char | 只有F8X16实现，Size=8时csize未初始化 | 仅放开str参数不足以修复 |
| include/oledfont.h | 只有F8X16及中文字库，没有6×8字库 | 需要完整的6×8字形及渲染支持 |
| test/host/support/Harness.h:HostOled | str忽略字号，只记录文本；refresh不使用真实驱动 | 既有测试无法捕获实际黑屏 |
| include/Oled.h | 文档已声明Size=8对应6×8字符 | 应补全现有契约，而不是把四行页面强塞成16像素 |

## 根因判断

页面在清屏后调用未实现的字号，str直接退出，最后将全零缓冲区发送到屏幕。这条确定的代码路径足以解释仅校准页黑屏；不需要更改分区、I2C频率或引脚。无法仅凭此证明没有其他硬件问题。

## 修复范围

- include/oledfont.h：添加固定6×8可打印ASCII字库，避免运行时缩放。
- src/Oled.cpp：write_char支持8像素字符并复用已有BMP裁剪；str支持6像素字宽及按实际字宽换行，保留16像素路径；拒绝字库外索引及不支持的字号，避免未定义读取。
- test/host/support/Harness.h、新增Wire.h、test/host/run.py及calibration_test.cpp：移除HostOled文本替身，编译真实Oled.cpp，只替代I2C硬件边界。
- 新增test/host/oled_test.cpp：验证真实6×8字形、四行像素、跨页/边缘裁剪、反色擦除、换行和16像素兼容；校准进入及四点流程检查真实GRAM，不能仅检查字符串。

## 不包含

不改变校准状态机、温控参数、加热流程、分区、I2C配置或原有菜单布局。无需修改公开函数签名；项目没有配置语言服务器。

## 风险与验证要求

- 小字必须在四个8像素行内可辨认，不能只验证非空或绕过实际驱动。
- 用真实OLED缓冲区生成128×32图像，人工查看字号、字符和四行布局；图像不是实物点亮证明。
- 一次运行完整现有主机校准行为检查及新增OLED检查，保留停热、队列满退出和保存等覆盖。
- 编译ESP32-C3固件，并检查最终.bin长度仍适配应用分区。
- 若目标板重新可达且仍隔离加热电源，烧录后由用户观察进入校准确认页；不能在隔离情况未知时启动校准加热。
- 当前缺失证据：真实OLED页面、I2C电气行为。不能以主机模拟或编译通过声明实物已经修复。
